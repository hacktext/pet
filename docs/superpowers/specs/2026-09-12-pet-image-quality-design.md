# 宠物画质优化（清晰度 + 亮度）设计

日期：2026-09-12 · 状态：已与用户确认设计，待写计划 · 分支：`feat/aipet-main-window`

## 1. 背景

用户对比竞品「宠伴赛博陪伴」的体验版金毛，觉得我们的宠物"毛发不清晰、亮度低"。实测（同为 960×960 的
stand 第 30 帧，只统计宠物主体，详见 `HANDOFF.md` 第 4 节"画质差距实测"）：

| | 我们（kling-v3 std 直出） | 竞品体验版金毛 |
|---|---|---|
| 码率 | 2.8 Mbps | 8.1 Mbps（服务端转码过） |
| 清晰度（主体平均 \|拉普拉斯\|） | 5.71 | 10.86 |
| 平均亮度 / 95 分位 | 118.5 / 190.9 | 162.4 / 221.6 |

结论：差距主要来自**生成的素材**——参考图本身偏暗（亮度 127.9），且 1k 参考图里的狗被**放大**进
1024 画布（`compose.py:61-62`）；再叠加 std 档与低码率。客户端有两处小损失：抠像缓存缩到 720；
`ApplyDespill` 对所有像素做 `G = min(G, (R+B)/2)`，会把偏黄的毛色压向橙色。

用户决定三项都做：① 客户端、② 成片处理、③ 用改进的配方重新生成（先试一段再定全量）。

## 2. 目标与验收标准

对处理后的成片（宠物主体，第 30 帧）：

- **亮度**：平均亮度落在 145–165；95 分位不超过 235（不过曝）。
- **清晰度**：主体平均 \|拉普拉斯\| ≥ 9（竞品 10.86，现状 5.71）。
- **可抠**：背景仍是纯 #00FF00；`petgen qa` 的抠像门槛（blob-core < 200）、接缝规则、格式
  （960×960 / 24 fps / 121 帧）全部照旧通过。
- **视觉**：并排对比图由用户认可。
- 客户端：`flutter analyze` 零问题、全部测试通过；原生 ctest 全部通过。

## 3. 设计

### ① 客户端（免费）

- **抠像缓存 960**：`pet_window_app.dart` 里 `AlphaVideo.prepare(..., targetEdge: 720)` 改为 960
  （提成常量）。`kMattePipelineVersion` 由 `p1` 改为 `p2`，旧缓存的键自然失效。
  代价：每个动作磁盘约 42 → 75 MB，首次抠像时间约 ×1.8。旧的 `p1` 文件不自动清理（缓存 LRU 本来就未做，记入 HANDOFF）。
- **去溢色只作用于半透明边缘**：`matte_core` 的 `ApplyDespill` 改为按透明度加权——
  `G' = G − (1 − a/255) · max(0, G − (R+B)/2)`。完全不透明（a = 255）的像素不变；完全透明的按原公式处理。
  调用顺序不变（键控出 alpha → 去溢色 → 预乘）。
  > **修正（2026-09-13，真机验收 A6 发现）：这个公式是错的，已换成最大值限制 `G' = min(G, max(R, B))`，缓存升 `p3`。**
  > 它把键控 alpha 当成了真实覆盖率；但键控过渡带很陡（innerT 0.28 → outerT 0.45），含大量绿幕的毛边拿到很高甚至 255 的
  > alpha，绿色几乎没被去掉——桌面上每只宠物都出现一圈细绿边（布偶猫实测 67 个强偏绿像素，改动前是 0）。
  > 最大值限制把高于 R、B 两者的绿色全部去掉，而金黄毛色（G ≤ R）、偏青的蓝眼睛（G ≤ B）天然不动；
  > 离线复刻中四段素材的偏绿像素都为 0，不透明毛色只改动 0.5–2.6%（旧公式 3.9–10.7%）。

### ② petgen 成片处理（新命令 `finish`）

输入 Kling 下载的 `<action>.mp4`（std 为 960×960，pro 可能更大），输出 `<action>-final.mp4`。
原片保留不覆盖；`qa` 和 `package` 改用 `-final.mp4`。

逐帧流程：

1. ffmpeg 解码成 RGB；若大于 960×960，先用面积平均缩到 960×960。
2. **按绿幕取 alpha**：沿用 `pet_matte` 的 YCbCr 色度距离键控参数
   （keyCb −0.331、keyCr −0.419、innerT 0.28、outerT 0.45），得到软 alpha。
3. **分离前景**：半透明像素按 `fg = (px − G·(1−a)) / a` 从绿中解出宠物颜色（a 很小时截断）。
4. **调色（只动宠物）**：
   - 曝光：gamma 提亮，使主体平均亮度达到目标 155。**系数按宠物统一**——从该宠物 stand 片段第 30 帧算出，
     同一系数用于它的全部动作（动作间一致，同一片段内无闪烁，首尾帧处理相同故接缝不受影响）。
   - 饱和度 ×1.10。
   - 锐化：USM（半径约 1.5、强度约 0.8、阈值约 2），按 alpha 加权，只作用于宠物。
5. **合回纯绿**：`out = fg' · a + #00FF00 · (1 − a)`。
6. 编码：libx264，`-crf 16 -preset slow -pix_fmt yuv420p`，24 fps，保持 121 帧；记录实际码率（预期 6–9 Mbps）。

系数由 `finish --pet <p>` 在首次运行时写入 `work/<pet>/grade.json`，后续动作复用；可用参数覆盖。

## 4. 错误处理与安全

- 可灵密钥只从 `secrets\kling.env` 读取，任何日志不打印密钥。
- 每次生成视频前检查余额；不足即停。
- `finish` 失败（解码失败、alpha 全空、帧数不对）不产出文件，返回非零。
- 调色后若主体 95 分位超过 235，先降低提亮再继续（避免白色毛发过曝）。

## 5. 测试

- **原生**：`test_despill` 先写失败测试——不透明黄色像素（例如 240,210,120,a=255）保持不变；
  半透明绿边（a=128）的 G 被按权重压低；完全透明像素与旧公式一致。
- **petgen**（pytest）：`finish` 只改变宠物像素，a=0 处精确为 #00FF00；输出 960×960 / 24 fps / 121 帧；
  同一宠物各动作使用同一系数；大于 960 的输入被缩到 960；过曝保护生效。
- **客户端**：更新涉及缓存键和 targetEdge 的测试；`flutter analyze` / `flutter test` 全绿。
- 生成相关的部分（真实调用可灵）不写自动化测试，靠试生成的数值与并排图验收。
