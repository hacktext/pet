# 正脸素材（正脸待机 + 喂食 + 玩耍）设计

日期：2026-09-19 · 状态：用户已确认（"可以，你直接做"） · 分支：`feat/aipet-main-window`

## 1. 背景

用户对比竞品：竞品待机时宠物**正脸朝向用户、动作幅度大**，我们是侧脸、几乎不动；竞品有**喂食**（碗里吃东西）和**玩耍**（玩球）。
同一轮提出的"悬停面板 / 养成数值 / 走路横穿屏幕"是另一个子项目（E，客户端），不在本文档。

spike（2026-09-19，金毛，结果见 `HANDOFF.md` 第 4 节）已证明：

- 正脸参考图 + `image = image_tail` 的 pro 待机：无缝循环（接缝 40.61 dB ≥ 片内最大跳变 26.42），抠像干净，
  第 30 帧亮度 153.6、清晰度 9.59，动作幅度 29.0（现有侧脸待机 10.4，竞品 35.7）。
- 让模型"碗出现、碗消失"会**溶解**：碗半透明的几帧里红色与绿幕混成橄榄绿鬼影，blob-core 最高 8072。
- 竞品的玩球片段里，球从首帧到末帧都在——道具全程在场是竞品的做法，也绕开了溶解。

## 2. 目标与验收

每只宠物（金毛、柯基、布偶猫）7 个动作：待机 `stand`、走路 `walk`、睡觉 `sleep`、喂食 `feed`、玩耍 `play`、
舔爪子 `lick_paw`、卖萌 `act_cute`。

- 待机、喂食、玩耍、舔爪子、卖萌都从**同一张正脸参考图**的姿势开始、回到该姿势结束（切换不跳）；走路、睡觉沿用现有成片。
- 待机：头正对镜头，整段有明显动作；无缝循环。动作幅度（主体上逐帧与首帧平均差）≥ 20。
- 喂食、玩耍：道具（碗 / 球）从首帧到末帧都在，没有半透明的道具帧。
- `petgen qa` 全过：格式 960×960 / 24 fps / 121 帧；接缝规则；**每 6 帧抽一帧**的 blob-core 都 < 200（新增，原来只查首末帧）。
- 画质沿用 2026-09-12 的标准，按 stand 第 30 帧：亮度 145–165、95 分位 ≤ 235、清晰度 ≥ 9。
- 并排图肉眼检查：同一只宠物、动作对得上名字、道具在爪前、没有鬼影。
- pytest 全过；客户端 `flutter analyze` / `flutter test` 全过（客户端代码不改：一次性动作回待机、`吃饭 / 玩耍` 名字都已存在）。

## 3. 设计

### 3.1 正脸参考图

新姿态 `front`：「正面朝向镜头站立，身体只微微侧转约十五度，头部正对镜头，嘴巴微微张开……」（spike 原文），画幅 `1:1`，
2k、bright、gate 时 `--calibrate`（与 2026-09-12 配方相同）。金毛直接用 spike 的参考图与待机成片。

### 3.2 道具：生成一次，合成进参考图

- `petgen prop bowl|ball`：文生图（kling-v3，无参考图，`1:1`、1k），浅灰底上一个哑光红色陶瓷碗（装满颗粒粮）/ 一个红色小球；
  用与 `compose` 相同的分割（BiRefNet-lite + matting）抠出，存 `work/props/<kind>-cutout.png`。所有宠物共用。不做曝光校准（会把红色提成粉色）。
- `petgen propref <pet> --tag T`：把 `ref-front-cutout.png` 按 `compose` 完全相同的方式放到 1024 画布上，再把道具贴在前爪前面，
  合成到纯绿，得到 `ref-front-bowl-green.png`、`ref-front-ball-green.png`，并跑同样的 gate 打分。
- 摆放规则（纯函数 `prop_box`，在 1024 画布上）：主体高度 `H` = alpha 包围盒高度；水平中心 = 主体最上面 20% 行里 alpha 的列中心
  （正脸时头在前腿正上方）；碗宽 `0.35·H`、球宽 `0.14·H`，高度按道具图比例；道具底边 = 主体底边 + `0.03·H`（在爪子前面、略靠下）；
  整体夹在画布内（四边留 8 px）。

### 3.3 视频提示词

`stand`、`feed`、`play` 按物种分猫、狗两套（猫不"张嘴吐舌"，吃"猫粮"，玩球用前爪拍）。喂食、玩耍都明确写"碗 / 球始终在原地，不消失"，
并以恢复到原来面朝镜头的站姿结束。`lick_paw`、`act_cute` 提示词不变，参考图换成正脸。
动作到参考图：`stand / lick_paw / act_cute → front`，`feed → front-bowl`，`play → front-ball`，`walk → walk`，`sleep → lie`。

### 3.4 质检、打包、配额

- `qa` 增加逐帧抽查：每 6 帧抽一帧按 gate 同样的方法打 blob-core，报告最差值并纳入通过条件。
- `package`：动作顺序 `stand walk sleep feed play lick_paw act_cute`；封面改取 `ref-front-cutout.png`（正脸）。
- `VIDEO_UNITS["pro"]` 由预估的 10 改为实测的 4（否则余额 4–9 时会被误拦）。
- 工作目录：三只都用 `--tag v3`。金毛从 `v3front` 复制 spike 产物、从 `v2pro` 复制 `walk / sleep` 成片；
  柯基、布偶猫从 `work/<pet>/` 复制 `walk / sleep` 成片。每只宠物的调色系数取自新 `stand` 第 30 帧。

### 3.5 额度

视频（pro，每段 4 单位）：金毛 feed / play / lick_paw / act_cute 16；柯基、布偶猫各 stand / feed / play / lick_paw / act_cute 20，共 **56**。
开工时余额 3，用户续购。图片：道具 2 × 8、柯基 / 布偶猫正脸参考图 2 × 8，共约 32（余 800）。
**额度不够就停下问用户，不降档；gate 或 qa 失败同配方重来一次，再失败就停下报告。**

## 4. 测试

- `prop_box`：用合成的 alpha 验证尺寸比例、水平中心跟头走、底边位置、贴边时被夹回画布内。
- 画布摆放抽成共享函数，`compose` 与 `propref` 共用；测试同一张抠图两条路径的狗像素一致。
- 逐帧 blob-core：合成一段中间几帧有半透明色块的小视频，最差值被抓到；干净视频为低值。
- 提示词：每个动作都映射到一张参考图；猫狗的 stand / feed / play 不同；喂食 / 玩耍提示词写明道具不消失。
- `pet_json` 的动作顺序、封面取正脸抠图。

## 5. 不在范围

悬停面板、养成数值、走路横穿屏幕（子项目 E）；走路 / 睡觉重生成；4k 档；道具的阴影。
