# 付费人物（单个买断）设计

日期：2026-10-21。涉及两个仓库：客户端 `aipet`（本仓库）、后端 `C:\Users\Administrator\code\pixpick\pixpickweb-tp`（ThinkPHP）。

## 1. 要做什么、为什么

用户新给了 5 个人物（`pic/4.png`–`pic/8.png`，单张正面全身照，带场景背景）。要：

1. 把这 5 个人物做成和现有内置人物一样的桌宠：抠像、4 个动作、语音。
2. 这 5 个人物**付费解锁**：每个人物单独买断，一个人物一个固定价格，价格在后台设置。宠物库里要一眼看出哪些是付费的。

目的是开始有人物内容的收入，并且以后上新付费人物不用发新版客户端。

## 2. 用户已经定下的

- **单个买断**，一个人物一个价格（不分标准版 / 高级版），价格在后台改。
- **付费人物的视频和语音不打进安装包**，放在后端的私有存储（阿里云 OSS 私有桶），付款后才发下载链接。理由：打进安装包只在界面上锁，翻安装目录就能拿到。
- **付款后卡片上出现「下载」按钮**，用户点了才下载；下完就和免费人物一样用（带TA回家 / 换TA陪我、右键菜单、声音等）。
- 不做：爱心、预览、搜索、排序（与之前宠物库的决定一致）。

## 3. 目标 / 非目标 / 反目标

**目标**
- 5 个新人物的素材质量与现有人物一致：2k 参考图、kling-v3 pro 5 秒、首尾同帧无缝循环、`qa` 全部通过、每人 3 种声音。
- 宠物库「人物」分类里，付费人物和免费人物放在一起，付费的有明显标记和价格。
- 微信扫码支付，复用定制宠物现成的下单 / 支付 / 回调流程和支付页。
- 解锁跟账号走：同一账号在另一台电脑登录后，卡片直接是「下载」，不用再买。
- 后台能改价格、上下架、排序，能看谁买了；以后再上新付费人物，只需上传素材 + 后台配一行，不用发版。

**非目标**
- 会员、打包购买、优惠券、赠送、试用。
- 退款流程的客户端界面（后台照常可退款，见 6.5）。
- 付费宠物（动物）——本次只有人物，但数据结构不写死「人物」。

**反目标（做成这样就算失败，哪怕功能能跑）**
- 不付钱也能从安装包或网络上直接拿到付费人物的视频 / 语音。
- 付了钱却拿不到、或换电脑要重新付。
- 付费人物在宠物库里和免费人物分不清，用户点了「带TA回家」才发现要钱。

## 4. 目录与数据：付费人物从后端来

付费人物的「目录」放在后端，不放在客户端：

- 后端返回付费人物列表：编号 `code`、名字、类别（男生 / 女生 / 二次元）、简介、标签、价格（分）、卡片照链接、声音列表（id + 名字）、动作列表、**当前账号是否已购**。
- 客户端把这份列表和卡片照**缓存在本地**（应用数据目录下），离线时也能显示上次看到的付费人物；从没拉到过就不显示付费人物，不报错。
- 本机已安装的付费人物，桌宠 id 为 `paid-<code>`，装在用户的宠物目录 `pets/paid-<code>/`（和定制宠物同一个目录），`pet.json` 的 `origin` 为新值 `paid`。

**我（Claude）的决定**：目录走后端而不是把 5 张卡片照打进安装包——这样上新、改名、改价、下架都不用发版，也是「以后上新不发版」这个目标的前提。

## 5. 客户端

### 5.1 卡片的四种状态（只针对付费人物）

| 状态 | 卡片照角标 | 按钮 |
|---|---|---|
| 未购买 | 「付费」 | 「¥19.9 解锁」（价格来自后端） |
| 已购买、本机未安装 | 「已购」 | 「下载」 |
| 下载中 | 「已购」 | 「下载中 42%」（不可点） |
| 已安装 | 「已购」 | 与免费人物相同：带TA回家 / 换TA陪我 / 陪伴中 / 正在准备… |

- 已安装的付费人物，声音行、右键菜单、悬停面板等全部和免费人物一样。
- 下载失败：按钮回到「下载」，弹一句「下载失败，请重试」；已校验过的文件保留，再点接着下。

### 5.2 解锁流程

1. 点「¥x 解锁」：未登录 → 打开登录页（提示「登录后即可解锁」），登录成功回到宠物库；已登录 → 下一步。
2. 后端下单，客户端打开**现有的微信扫码支付页**（定制流程里的那页），显示人物名和价格。
3. 支付页轮询到「已支付」→ 关闭支付页，卡片变「下载」，并提示「解锁成功，点下载即可使用」。
4. 点「下载」→ 下载、逐个文件校验大小和 sha256 → 整体移入 `pets/paid-<code>/` → 卡片变「带TA回家」。

### 5.3 谁来下载

- 宠物库窗口只负责界面和发请求；**下载、写宠物目录仍由桌宠窗口做**（它是宠物目录唯一的写入者，现有原则不变）。宠物库点「下载」→ 通过两窗口之间的通道请桌宠窗口下载 → 桌宠窗口推送进度和完成。
- 下载 / 校验 / 断点续传 / 原子安装复用 `CustomDownloader` 的做法（`.downloading` 暂存、`.part`、一次目录改名）。
- 已购人物**不自动下载**，只在用户点「下载」时下（用户的要求）。

### 5.4 登录态变化

- 登出：已安装的付费人物保留在本机，但卡片回到「未购买」样式、不能再领养；若它正在桌面上，换回一个免费宠物（或第一个已领养的免费宠物）。
- 换账号登录：按新账号的「已购」重新判断。
- 离线或登录过期：**沿用缓存里的「已购」**，不锁；只有明确登出、或新拉到的目录说「未拥有」时才锁。（**我的决定**，最贴近反目标「付了钱却用不了」。）
- 另一台电脑同步过来「当前宠物是某付费人物」但本机还没下载：现有同步逻辑本来就跳过本机不完整的宠物，所以不会自动下载、也不会出错；卡片显示「下载」。

## 6. 后端

### 6.1 表（手写 SQL，按 `database/migrations/` 现有风格，可重复执行）

- `aipet_characters`：`code`（唯一）、`name`、`species`（girl / boy / anime）、`blurb`、`tags`（JSON）、`price_cents`、`voices`（JSON）、`actions`（JSON）、`sort`、`enabled`、时间戳。带 `product_id`，按现有 `ProductScoped` 约定。
- `aipet_character_assets`：`character_code`、`path`、`bytes`、`sha256`、`oss_key`、`kind`（`card` / `file`）。
- `aipet_character_unlocks`：`user_id`、`character_code`、`order_no`、`unlocked_at`、`revoked_at`；`(user_id, character_code)` 唯一。
- `aipet_character_orders`：`order_no` → `character_code`、`user_id`。**我的决定**：微信回调会覆盖 `orders.payload`，所以和定制宠物的 `aipet_custom_orders` 一样，用一张关联表记住订单买的是谁。
- 初始数据：5 个人物各一行，价格先填 1990（¥19.9），**`enabled=0` 不上架**，等用户在后台设好价格再上架。

### 6.2 接口（都过 `AipetProduct::guard()`）

| 接口 | 登录 | 作用 |
|---|---|---|
| `GET /api/aipet/characters` | 可选 | 上架的付费人物列表（第 4 节的字段 + 卡片照签名链接）；带 token 时每项带 `owned` |
| `POST /api/aipet/characters/:code/order` | 必须 | 下单，返回与定制下单相同的结构 `{order_no, amount_cents, code_url, expired_at, expires_in}`；已购返回明确的错误码；未支付的同人物订单在有效期内复用 |
| `GET /api/aipet/characters/orders/:orderNo` | 必须 | 订单状态 `{status}`，供支付页轮询 |
| `GET /api/aipet/characters/:code/assets` | 必须 | 已购才返回 `{pet_id, files:[{path, bytes, sha256, url}]}`（签名、限时），否则 403 |

- 订单进共享的 `orders` 表，`plan_code='aipet_character'`、`period='once'`，金额以下单时 `aipet_characters.price_cents` 为准（改价不影响已下的单）。
- 微信回调走现有 `Fulfillment`，新增 `aipet_character` 分支：写一行 `aipet_character_unlocks`；重复回调幂等。
- 后台 `admin/Orders.php` 里「标记已支付」和「退款」各自按 `plan_code` 分支直接调服务，`aipet_character` 也要在这两处加分支（否则后台手动标记 / 退款对付费人物无效）。
- 下架（`enabled=0`）：不在列表里，不能下单；**已购的人仍能下载**（assets 接口只看是否已购）。

### 6.3 素材上传（开发机 → 后端）

- 新增内部接口（和 petgen worker 同一套 worker key 鉴权，挂在 `internal/aipet/*` 下）：
  - 申请上传：给出文件清单，返回每个文件的 OSS 签名 PUT 链接；
  - 完成：提交每个文件的 path / bytes / sha256，写入 `aipet_character_assets`。
- petgen 加一个命令，把做好的人物目录（`pet.json`、4 个 mp4、`voices/`、卡片照）一次上传。

### 6.4 后台

- 新页面「付费人物」：列表（名字、价格、上架、素材文件数、已购人数），编辑名字 / 简介 / 标签 / 价格 / 排序 / 上架。
- 现有「订单」页能看到这些订单（`plan_code=aipet_character`），退款照常。

### 6.5 退款

- 后台对这类订单退款时，把对应的 `aipet_character_unlocks` 标 `revoked_at`。之后 `owned` 为假、assets 接口 403。
- 客户端下次拉目录发现不再拥有：按 5.4「登出」同样处理（保留文件但不能用，卡片回到「未购买」）。

## 7. 素材生产

- 配方同 `tools/petgen/work/chars/spike.py`（本月做铃音 / 林阳 / 小柚的那份）：从正面照用可灵 subject 参考生成 2k 浅灰底参考图 → 本地抠像合成绿底 → kling-v3 pro 4 个动作（待机 / 撒娇 / 跳舞 / 说话）→ `finish` → `qa` → 火山 TTS 每人 3 种声音 → 卡片特写照（可灵生成，同宠物库现有卡片）。
- 名字、简介、标签由我起初稿，用户可在后台改。
- **额度**：视频 5 人 × 4 段 × 4 单位 = 80 单位，现余额 80.6，没有重做余地。先做 5 段「待机」看效果，再决定是否续购后做其余；不够就停下问用户，不降级。图片约 5 ×（8 参考 + 8 卡片）= 80 单位，余额够。
- 做好的人物目录**不进 git、不进安装包**，只上传到后端。
- **代码不等素材**：客户端和后端用一个测试人物（拿现有某个人物的素材上传成 `test` 编号）先做完、测完；5 个真人物的素材做好后再上传、上架。额度用完而用户暂不续购时，代码部分照常交付。

## 8. 测试与验收

- 客户端：目录解析与缓存、四种卡片状态、未登录点解锁、支付成功后变「下载」、下载校验失败重试、登出 / 退款后不能领养、通道消息往返——单元 / 组件测试。
- 后端：下单（已购拒绝、复用未付订单、金额取当时价格）、回调幂等、assets 未购 403 / 已购 200 / 下架仍可下载、退款撤销——按后端现有测试方式。
- 真机验收（需用户同意或用户自己做）：用后端的假支付通道或后台「标记已支付」走一遍：解锁 → 下载 → 领养 → 换电脑登录直接下载。

## 9. 留给实现者决定的

- 客户端缓存的文件名和位置、卡片照的缓存策略。
- 卡片照签名链接的有效期（建议比素材下载长，如 1 天）。
- 支付页复用时具体怎么把「人物名 + 价格」传进去。
- 下载进度推送的频率。
- 角标的具体样式（颜色沿用当前奶油 / 杏橙配色）。
