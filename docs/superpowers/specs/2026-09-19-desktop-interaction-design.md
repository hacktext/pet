# 桌面互动（悬停面板 + 养成数值 + 走路横穿屏幕）设计

日期：2026-09-19 · 状态：用户已确认（"可以"） · 分支：`feat/aipet-main-window` · 子项目 E

## 1. 背景

用户对比竞品（截图见 2026-09-19 对话）：鼠标移到宠物上会出现**状态面板**（名字、状态、陪伴天数、今日互动、亲密度 / 饱食度 / 健康度、
站立 / 行走 / 喂食 / 玩耍四个按钮）；宠物**走路时从屏幕一端走到另一端**，我们是原地踏步。
实测：竞品的走路片段本身也是原地走（主体水平中心 0.49–0.53），横穿是客户端移动窗口；竞品本地状态有
`stats{intimacy, satiety, health, companionStartedAt, interactionDay, todayInteractions}`（与父 spec 4.6 一致）。
正脸待机 / 喂食 / 玩耍的素材是子项目 F（`2026-09-19-front-facing-pets-design.md`），本设计只依赖它产出的动作键 `feed`、`play`。

用户选定：走动="点了才走，偶尔也自己走"；数值="轻度养成"；面板用独立窗口。

## 2. 目标与验收

- 鼠标移到宠物上约 0.3 秒后，宠物上方出现面板（上方放不下就在下方）；鼠标离开宠物和面板约 0.6 秒后收起；点 × 立即收起，直到鼠标离开宠物再回来。
- 面板内容与竞品截图一致：名字、状态文字、「陪伴 N 天」「今日互动 N 次」、三项数值（带进度条）、四个按钮。宠物没有的动作按钮置灰。
- 点「行走」或右键菜单「走路」：宠物朝空间大的一侧横向移动，到屏幕可用区域边缘转身，共 20 秒后回到待机；途中切换动作或拖动立即停。
- 待机 3–6 分钟（随机）后自己走 8–15 秒；悬停中、面板开着、正在拖动、正在准备素材时不自己走。
- 走路方向与片段朝向相反时画面水平翻转；只翻走路，其他动作不翻。
- 数值规则见 3.3；关掉软件期间按分钟补算（最多 30 天）；每只宠物各自一份，重启后保留。
- `flutter analyze` 零问题、全部测试通过；原生不改；真机验收（悬停、面板位置、走动、翻转、数值变化）另行进行。

## 3. 设计

### 3.1 窗口与通道

- 第三个引擎「面板窗」：宠物窗启动时用 `desktop_multi_window` 创建（参数 `hud_window`，`hiddenAtLaunch: true`），一直藏着，需要时显示。
  `main.dart` 按参数分派：`main_window` → 宠物库，`hud_window` → 面板，其余 → 宠物窗。
- 面板窗自己用 `window_manager` 设无边框、透明、置顶、不进任务栏、固定大小（逻辑 440×250），并自己定位：
  `WindowController` 只有 `show / hide`，所以宠物窗把自己的窗口矩形发给面板，面板用纯函数 `hudPosition` 算位置。
- 新通道 `aipet/hud`（双向配对，宠物窗 ↔ 面板窗；`aipet/pet` 已被宠物窗 ↔ 宠物库占用，每个通道最多两个引擎）：
  - 宠物窗 → 面板：`hudShow {bounds:[x,y,w,h], view}`、`hudUpdate {view}`、`hudHide`
  - 面板 → 宠物窗：`hudAction {key}`、`hudClose`、`hudHover {inside}`
  - `view`（`HudView`）：`name, status, companionDays, todayInteractions, intimacy, satiety, health, actions{stand,walk,feed,play}`
- 宠物窗仍是**唯一写文件的一方**（`settings.json` 之外新增 `stats.json`）。
- 风险：子窗口透明未实测（宠物窗的透明完全由 `window_manager` 实现，runner 无额外代码，子引擎同样注册了插件）。
  若透明不生效，面板改为铺满窗口的不透明圆角卡片（四角露出窗口底色），不影响功能。

### 3.2 悬停与显示逻辑

纯状态类 `HudPresenter`（计时器可注入）：输入 `petEnter / petExit / hudEnter / hudExit / closeClicked / busy(walking|dragging|noPet)`，
输出 `show(bounds) / hide()`。规则：鼠标在宠物上连续 300 ms 且不忙 → 显示；鼠标既不在宠物也不在面板上 600 ms → 隐藏；
点 × → 隐藏并置 `dismissed`，鼠标离开宠物后清除；走路或拖动开始 → 立即隐藏。命中区域先用宠物窗整个矩形（逐像素命中测试不在本期）。

### 3.3 养成数值（轻度养成）

`PetStats`（每只宠物一份）：`intimacy`、`satiety`、`health`（0–100，小数存储、显示取整）、`companionStartedAt`、`interactionDay`（本地日期）、
`todayInteractions`、`updatedAt`。新领养：亲密 50、饱食 50、健康 100。

- 饱食度：每小时 −100/24（24 小时由满到空）；喂食 +30，上限 100。
- 健康度：饱食度 < 20 时每小时 −2；饱食度 ≥ 50 时每小时 +5（到 100 为止）；其余不变。
- 亲密度：每次用户互动 +1，上限 100，不衰减。用户互动 = 从面板或右键菜单触发任何动作（含喂食、玩耍、行走、站立）；自动走动不算。
- 今日互动：互动时 +1；本地日期变化后清零。陪伴天数 = 本地日期差 + 1。
- 状态文字：健康 < 60「不太舒服」；否则饱食 < 20「饿坏了」；< 50「有点饿了」；否则「状态很好」。
- 时间推进：按分钟逐步积分（饱食变化会跨过 20 / 50 的阈值），最后不足一分钟按比例；最多补 30 天。
  宠物窗每分钟推进一次并在变化时保存；启动时先补算再显示。

`stats.json`：`{"schema":1,"pets":{"<petId>":{...}}}`，写法同 `settings.json`（临时文件 + 改名；读不了就改名 `.bad` 当作空）。

### 3.4 走路

- 纯类 `Walker`：给定窗口左边界的活动范围 `[minX, maxX]`、起点、方向、时长、速度（默认 90 逻辑像素 / 秒）；`step(dt)` 前进，
  到边界反向（多出的距离折返），时长用完返回结束。起始方向 = 空间大的一侧。
- 活动范围 = 宠物窗所在显示器的可用区域（`screen_retriever`，逻辑像素，与 `window_manager` 同一坐标系）减去窗口宽度；高度不变。
- 宠物窗以约 30 fps 的定时器驱动 `Walker` 并 `setPosition`；走路时播 `walk` 循环片段；结束回 `stand`。
- 自动走动：回到待机后按 3–6 分钟随机计时；到点时若空闲（当前待机、面板未显示、鼠标不在宠物上、未拖动、未准备素材）就走 8–15 秒，否则重新计时。
- 朝向：`pet.json` 新增可选字段 `walkFacing`（`left` / `right`，缺省 `right`）；走向与朝向相反时 `Transform.flip(flipX)`。
  petgen `package` 从 `walk-final.mp4` 首帧自动判断（主体上 1/4 的像素重心在哪一侧即头在哪侧）；现有三只内置宠物的 `pet.json` 先手工补上
  （实测：金毛 left，柯基 right，布偶猫 right）。

### 3.5 面板界面

按竞品截图：浅粉白圆角卡片；左上头像（宠物封面圆形裁切）+ 名字 + 状态；右上「陪伴 N 天 / 今日互动 N 次」胶囊 + ×；
三格数值（亲密度粉、饱食度橙、健康度绿，百分数 + 细进度条）；四个按钮（站立 🐾、行走、喂食、玩耍），不可用时置灰。

## 4. 错误处理

- 面板窗创建失败或通道不通：只记日志，宠物窗照常工作（悬停不出面板）。所有 `hud*` 调用都有超时、失败不抛。
- `stats.json` 读不了：改名 `.bad`，当作新宠物数值；写失败只记日志（与 `settings.json` 相同）。
- 走路时显示器信息取不到：不走，直接回待机。

## 5. 测试

- 纯函数 / 纯类单测：`PetStats` 推进（阈值跨越、上限下限、30 天封顶、跨天清零、陪伴天数）、互动与喂食、状态文字；`Walker`（前进、到边转身、
  时长、范围过窄）；`hudPosition`（上方、翻到下方、左右夹取）；`HudPresenter`（延时显示 / 隐藏、× 后需离开再进入、忙时不显示）；
  `walkFacing` 解析；`StatsStore`（往返、坏文件隔离）；桥（假传输层验证消息与参数）。
- 组件测试：面板渲染数值与置灰、按钮发出 `hudAction`。
- petgen：`walk_facing` 用合成片段测左右。
- 真机验收：悬停出现 / 收起、面板位置与翻转、行走横穿与转身、自动走动、翻转方向、数值随时间和喂食变化、重启保留。

## 6. 不在范围
